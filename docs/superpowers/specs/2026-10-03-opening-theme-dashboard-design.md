# 开盘题材动态强弱看板设计

- 日期：2026-10-03
- 状态：书面规格已确认
- 上游阶段：`2026-10-02-opening-strength-premarket-design.md`
- 部署目标：`http://115.191.14.82:8000/#/opening-themes`

## 1. 目标与成功标准

本阶段把已经冻结的盘前归因快照接入分时行情，新增独立顶部 Tab“开盘题材”。用户可以从 09:30 起观察题材强弱、加速、扩散、支撑度、集中度、数据健康度和贡献个股，并可以选择历史交易日和盘中时点进行回溯。

成功标准如下：

1. 实时模式每 3 秒刷新，但只消费当天已冻结快照，不在页面请求中运行或修改盘前归因。
2. 历史模式使用所选日期的冻结归因和历史分时按需重算，不保存实时排名快照。
3. 所有强弱结果只覆盖三个源股池的候选股票，以及每只股票盘前冻结的 1～3 个行业或概念。
4. 主榜、加速榜、扩散榜和贡献个股可以解释到原始指标；首版不使用不透明的综合分。
5. 无快照、非交易时段、部分行情缺失和行情获取失败都有明确、可恢复的页面状态。
6. 不改变现有板块、自选、竞价、扫描、管理和知识图谱看板的接口与行为。
7. 自动化测试、前端构建和生产 UI 冒烟验证通过后，部署到现有 `ifind-monitor` 服务。

## 2. 已确认范围

### 2.1 纳入范围

- Theme 类型：行业 `884xxx`、概念 `885xxx/886xxx`。
- 候选来源：高贝塔值、近期强势、同花顺热股。
- 时间范围：连续竞价自 09:30 开始；午间保留最后有效分钟；首版不展示 09:15～09:25 集合竞价。
- 模式：当天实时、历史日期和历史盘中时点回放。
- 布局 A：左侧题材强弱榜，右侧加速榜与扩散榜，下方是所选题材的贡献个股明细。
- 传输方式：REST 请求，实时自动跟随时每 3 秒轮询。
- 前端测试：新增 Vitest 和 Vue Test Utils，仅作为开发依赖。

### 2.2 不纳入范围

- 自定义静态板块。
- 集合竞价排名。
- 新闻或大模型题材识别。
- 盘中重新归因、修改 Membership 或替换冻结快照。
- 自动盘前调度。
- WebSocket、Kafka、Flink 或新的数据库表。
- 永久保存分钟级排名结果。
- 成交额、换手率或流动性因子参与排序。

## 3. 方案选择与架构边界

采用“独立开盘聚合服务”方案。新增服务复用 `IntradayFetcher` 获取分时序列，自己维护按交易日和候选股票集合区分的短期缓存。它不导入或调用 `RealtimeEngine` 的私有方法，也不重构旧看板的缓存和计算路径。

选择这一方案的原因是：旧实时引擎服务现有生产看板，直接复用其私有缓存会形成隐式耦合，而提取全站共享缓存会扩大本阶段回归范围。开盘题材的候选集合已经去重，独立服务仍保证在本模块中每只股票只抓取、缓存和计算一份行情。

模块职责如下：

| 单元 | 职责 |
|---|---|
| `opening_strength/realtime_models.py` | 定义股票时点、题材指标、贡献明细和看板结果的不可变模型 |
| `opening_strength/realtime_aggregation.py` | 纯函数计算时点指标、排名、风险标签和贡献排序 |
| `opening_strength/dashboard_service.py` | 加载冻结快照、构建候选和倒排索引、协调行情提供器与聚合器 |
| `opening_strength/quote_provider.py` | 适配 `IntradayFetcher`、缓存完整分时序列并切片到请求时点 |
| `api/routers/opening_strength.py` | 参数校验、服务调用和稳定 JSON 响应，不包含计算规则 |
| `frontend/src/views/OpeningThemesPage.vue` | 实时/历史控制、时间轴、状态展示和布局 A 编排 |
| `frontend/src/components/opening-themes/*` | 主榜、变化榜、贡献明细和指标提示组件 |
| `frontend/src/api/openingThemes.ts` | 开盘题材 API 类型和调用封装 |

`opening_strength/realtime_aggregation.py` 不得导入数据库、FastAPI、Vue 相关代码、`realtime_engine.py`、`theme_catalyst.py`、`features.py` 或 `attribution.py`。`dashboard_service.py` 只能读取 `FROZEN` 运行及其候选、Membership 和 Attribution，不得调用 `SnapshotService.run()`。

## 4. 数据流与缓存

一次看板请求按以下流程执行：

1. 校验 `trade_date` 为 `YYYYMMDD`，并将可选 `snapshot_time` 规范化为 `HH:MM`。
2. 读取该日期唯一的 `FROZEN` 运行；不存在时返回结构化的 `SNAPSHOT_NOT_FOUND`，不触发归因。
3. 读取候选、Membership 和 Attribution，按股票去重后构建 `stock→attributions` 与 `theme→stocks` 索引。
4. 行情提供器以交易日和排序后的候选代码摘要作为缓存键，通过 `IntradayFetcher` 批量获取完整日内分时。
5. 删除 09:30 之前的数据，生成当天已有的分钟时间轴；没有传 `snapshot_time` 时选择最新有效分钟。
6. 传入请求时点或时间轴所能提供的不晚于该时点的最新分钟，计算股票状态和题材指标。
7. 主榜按强度排序；加速榜和扩散榜使用各自变化指标；返回选中题材所需的贡献明细。

行情序列缓存遵循 stale-while-revalidate：当天数据 15 秒过期，历史日期在进程生命周期内视为稳定。并发请求对同一缓存键只允许一次上游抓取，其余请求读取最近成功结果或等待同一任务。成功聚合结果缓存 3 秒；冻结运行的 `run_id` 必须进入缓存键，确保人工替换快照后旧结果不会继续返回。

页面采用现有时间轴交互：自动跟随时轮询最新结果；拖动、播放或选择历史时点时停止自动跟随，只在时点变化时请求。组件进入 `keep-alive` 非激活状态时停止轮询和播放，重新激活后再刷新，避免隐藏 Tab 持续抓取行情。

## 5. 指标与排名口径

所有百分比字段以百分点表示，例如 `2.35` 代表上涨 2.35%。计算中保留全精度，API 输出四位小数，前端通常展示两位。

### 5.1 股票时点

对股票 `s` 在时点 `t`：

```text
return_s(t) = (last_s(t) / pre_close_s - 1) * 100
```

只有 `pre_close_s > 0` 且存在不晚于 `t` 的价格点时，该股票才是有效行情。09:30 的上一分钟指标使用 09:30 自身，因此 09:30 的加速和扩散变化均为 0。

### 5.2 题材强度

对题材 `g`，只使用具有有效行情的归因股票：

```text
level_g(t) = Σ(weight_sg * return_s(t)) / Σ(weight_sg)
```

这里的 `weight_sg` 是盘前冻结归因权重。无有效股票或有效权重和为零时，题材没有可排名指标。

主榜名称为“题材强弱榜”，默认按以下稳定顺序排列：

1. 有可排名指标的题材优先；
2. `level` 降序；
3. `momentum_1m` 降序；
4. `theme_code` 升序。

低支撑、单股驱动或数据覆盖不足不会被隐藏或篡改分数，而是通过标签和弱化样式表达可信度。用户可以点击列头按加速、扩散、支撑数或集中度排序。

### 5.3 加速与扩散

```text
momentum_1m_g(t) = level_g(t) - level_g(previous_minute)
up_ratio_g(t) = supporting_count_g(t) / valid_quote_count_g(t)
breadth_delta_1m_g(t) = up_ratio_g(t) - up_ratio_g(previous_minute)
```

`supporting_count` 是当前 `return_s(t) > 0` 的有效归因股票数量。加速榜按 `momentum_1m` 降序，扩散榜按 `breadth_delta_1m` 降序；两榜仅纳入 `valid_quote_count >= 2` 且 `data_health >= 0.60` 的题材，避免单股或严重缺数制造变化信号。

### 5.4 支撑、集中度与数据健康

- `attributed_stock_count`：冻结归因中属于该题材的去重股票数。
- `valid_quote_count`：请求时点具有有效行情的归因股票数。
- `supporting_count`：有效行情中涨幅大于 0 的股票数。
- `support_weight`：上涨股票归因权重之和 ÷ 全部有效股票归因权重之和。
- `source_pool_diversity`：上涨股票覆盖的源股池种类数，范围 0～3。
- `data_health`：`valid_quote_count / attributed_stock_count`。
- `positive_contribution_sg`：`max(weight_sg * return_s(t), 0)`。
- `top1_concentration`、`top3_concentration`：前 1/3 个正贡献之和 ÷ 全部正贡献之和；没有正贡献时为 `null`。

风险标签采用固定规则：

| 标签 | 条件 |
|---|---|
| `单股驱动` | `attributed_stock_count == 1` |
| `低支撑` | `attributed_stock_count > 1` 且 `supporting_count < 2` |
| `高度集中` | `top1_concentration >= 0.70` |
| `数据不足` | `data_health < 0.60` |
| `行情滞后` | 当天实时模式下最新有效分钟比当前中国标准时间落后超过 2 个已开市分钟 |

午间休市、盘前和收盘后不累计行情滞后分钟。成交额和换手率可在贡献明细中展示已有原始值，但首版不参与任何排名或风险规则。

### 5.5 贡献个股

个股贡献值为 `weight_sg * return_s(t)`。明细默认按贡献值降序，展示股票代码、名称、涨幅、归因权重、贡献值、来源池、归因置信度和原因码。负贡献保留并排在正贡献之后；缺失行情的归因股票列在末尾并标记“暂无行情”。

## 6. API 契约

新增只读接口：

```text
GET /api/opening-strength/dashboard
```

查询参数：

| 参数 | 必填 | 规则 |
|---|---|---|
| `trade_date` | 是 | `YYYYMMDD` |
| `snapshot_time` | 否 | `HH:MM`；省略时取最新有效分钟 |

成功响应至少包含：

- `trade_date`、`run_id`、`mode`、`snapshot_time`、`latest_time`、`available_times`；
- `candidate_count`、`theme_count`、整体 `data_health`；
- 完整 `themes` 列表，每项包含原始指标、风险标签和贡献个股；
- `acceleration_theme_codes` 与 `breadth_theme_codes`，分别按对应榜单顺序引用 `themes`；
- `generated_at` 和 `cache_status`，供运维与 UI 状态栏使用。

错误使用稳定 HTTP 状态和结构：

```json
{
  "error": {
    "code": "SNAPSHOT_NOT_FOUND",
    "message": "该日期尚未生成盘前冻结快照",
    "retryable": false
  }
}
```

| 场景 | HTTP | 错误码 |
|---|---:|---|
| 参数格式错误或时间早于 09:30 | 422 | `INVALID_REQUEST` |
| 日期无冻结快照 | 404 | `SNAPSHOT_NOT_FOUND` |
| 快照存在但没有可用时间点 | 503 | `QUOTE_DATA_UNAVAILABLE` |
| 上游行情失败且没有可用旧缓存 | 503 | `QUOTE_PROVIDER_FAILED` |

历史日期请求同一接口，不另建历史计算接口。请求晚于最后有效分钟的时点时选择最后有效分钟，并在响应中返回实际 `snapshot_time`；请求落在已有分钟之间时选择不晚于请求值的最近一分钟。

## 7. 页面设计与交互

顶部导航新增“开盘题材”Tab，路由为 `#/opening-themes`。页面按布局 A 组织：

1. 顶部控制栏：实时/历史模式、日期、当前冻结版本、行情时点和数据健康。
2. 时间轴：实时和历史均可使用；实时默认自动跟随，历史默认停在最后一分钟。
3. 左侧主区：题材强弱榜，展示强度、1 分钟加速、上涨/有效股票数、扩散变化、集中度、数据健康和标签。
4. 右侧窄栏：加速榜、扩散榜，各展示前 10 个有效题材。
5. 下方明细：点击任一榜单题材后展示贡献个股；刷新后保持仍存在的选择，否则自动选择主榜第一项。

实时模式的日期固定为当前中国标准日期且不可编辑。历史模式可选择任意日期，但只有存在冻结快照且有可用分时的日期能够产生结果。首版不自动执行“拉取并计算”或盘前命令。

页面状态必须区分：加载中、无冻结快照、行情暂不可用、部分数据降级、请求失败和正常。无快照状态给出可复制的人工命令：

```text
python main.py opening-premarket --date YYYYMMDD
```

该提示只提供操作说明，不在浏览器中执行命令。

## 8. 错误处理与安全降级

- 冻结快照是硬前置条件；不存在时绝不回退到实时 Membership，也不自动创建。
- 部分股票缺行情时继续计算，分母只使用有效行情权重，并用 `data_health` 和标签暴露缺失程度。
- 部分题材无任何有效行情时保留在主响应末尾，指标为 `null`，贡献明细仍列出冻结股票。
- 当天上游刷新失败但有最近成功缓存时返回旧缓存，并标记 `cache_status=stale`；没有缓存才返回 503。
- 历史日期上游失败不使用其他日期行情兜底。
- API 不返回密钥、上游原始异常文本或本地绝对路径；服务端记录带 `trade_date/run_id` 的错误摘要。
- 前端用递增请求序号丢弃过期响应，日期、模式或时点切换不会被先前慢请求覆盖。

## 10. 交付边界

本阶段交付代码、自动化测试、必要文档、生产静态资源和服务部署。生产页面是否出现真实排名取决于对应交易日是否存在冻结快照以及 iFinD 分时接口是否可用；这两项运行前置不通过伪造数据规避。

下一阶段可以单独设计自动盘前调度、运行状态告警、集合竞价信号或排名快照持久化。本阶段不为这些未来能力预留未使用接口。
